| 2026-09-18 | **0.14.0 正式版（vc39，覆盖 v0.14.0-preview vc38）** | **本版主题：虚拟屏与 AI 浏览器达到可用线。** **虚拟屏**：跨屏拉起四条候选路径实测只有「壳侧 Shizuku UserService + `am start --display <id> -n <component>`」成立（monkey 无屏幕维度 / shell `am start` 不稳 / 进程内 `setLaunchDisplayId` 被 SafeActivityOptions 拒），据此把唯一可行路径做通；补 `screenId` 可发现性（此前该参数无 description，设备实录证明模型直接忽略 → App 落到真实屏）；截图两条通道都认屏幕（ADB 回落此前完全忽略 screenId，抓的是真实屏——静默错误答案）；等比 letterbox 按内容宽高比居中；可见性判据补「侧栏已收起」；序号复用（旧实现单调递增从不回收）；会话隔离 + 销毁不设锁 + 10 分钟空闲回收；手动关机按钮。**AI 浏览器**：隔离宿主 WebView 可用；分辨率=CSS 视口（document-start 注入 + letterbox，innerWidth 精确）；PC/手机身份；多页签；browser_snapshot 渲染每行 ref；侧栏收起时视口不再塌成 0x0（GONE → INVISIBLE + layoutDetached，实测 0x0→450x800）；setInitialScale 在 API 36 stub 已移除 → 改注入实现。**附件入口分流（#215）**：回形针单击即出菜单（Tooltip 气泡插在按钮与 input 之间致兄弟相邻判据失效，改为结构判定）；显式图片类型分流到系统相册（此前壳侧为修「空 accept 受限视图」把相册分支整个删掉，两个入口打开同一界面）。**Shizuku 时序**：ensureBound 只 await 一片 4s 而 bind 实测约 5s、且 bindLatch 一次性不清空 → 「第一次必失败第二次必成功」是确定结果；改为总预算内循环等待 + 三路径清 latch + connecting/not-bound 拆成两个 code。**快照升级健壮性**：deletePath 逐项容错 + 残留 stage 改名挪开（此前一个删不掉的损坏 stage 会让之后每次启动都失败）。**坑位 139-143 登记**（Termux 报错风暴真因 / 回形针兄弟判据 / Shizuku latch 时序 / 截图忽略 screenId / 图片 accept 被壳侧统一入口吞掉）。**验收**：门禁全绿、Kotlin 269 项 0 失败、插件 82+62+12、UI 180、双 ABI exit 0。 | kelai141 |
